# ProductAI MVP Scope v1

Version: 0.1
Status: Draft

---

# 1. Overview

This document defines the Minimum Viable Product (MVP)
scope for ProductAI Phase 1.

The goal of the MVP is NOT to build
a fully autonomous AI company.

The goal is:

To build the smallest operational version
of an AI Product Organization OS.

---

# 2. MVP Philosophy

## Small is Beautiful

The MVP should remain:

- understandable
- modular
- local-first
- operationally visible
- easy to evolve

---

## Avoid Premature Complexity

The MVP should avoid:

- enterprise complexity
- over-automation
- excessive infrastructure
- fully autonomous execution

---

# 3. MVP Goals

The MVP should demonstrate:

- AI mission orchestration
- dashboard-based operations
- organizational memory
- worker visibility
- GitHub-centered workflows
- reflection-driven improvement

---

# 4. Included in MVP

## Dashboard UI

The MVP includes:

- CEO Home
- Mission Dashboard
- Worker Status Panel
- Memory Panel
- Incident Visibility

---

## Mission System

The MVP includes:

- mission creation
- mission state tracking
- milestone visibility
- task organization

---

## Worker Visibility

The MVP includes:

- worker runtime state
- assigned tasks
- current activity
- review state

---

## Memory System

The MVP includes:

- local-first memory
- Markdown storage
- reflection storage
- lesson tracking
- suggested recall

---

## GitHub Integration

The MVP includes:

- repository linking
- branch visibility
- commit visibility
- PR visibility

---

## Settings System

The MVP includes:

- runtime settings
- repository settings
- memory settings
- dashboard settings

---

# 5. NOT Included in MVP

## Full Autonomous Company

The MVP does NOT include:

- autonomous business management
- autonomous executive decisions
- autonomous financial control

---

## BusinessAI

BusinessAI remains a future phase.

Not included:
- CRM
- revenue systems
- billing
- marketing automation
- customer segmentation

---

## Enterprise Features

Not included:
- multi-tenant systems
- team management
- RBAC
- cloud-scale infrastructure

---

## Full Autonomous Workers

Workers remain:
- supervised
- review-oriented
- human-approved

---

# 6. MVP Technical Direction

## Frontend

Recommended:
- React
- Next.js
- Tailwind

---

## Backend

Recommended:
- Python
- FastAPI

---

## Storage

Recommended:
- SQLite
- Markdown

---

## AI Runtime

Initial support:
- Cursor
- Claude Code
- OpenAI APIs

Future support:
- Codex
- local LLM workers

---

# 7. MVP UI Philosophy

The MVP UI should feel:

- calm
- operational
- trustworthy
- transparent
- non-chaotic

---

## Preferred Style

- dashboard-first
- multi-panel
- resizable layout
- operational visibility
- low visual noise

---

# 8. MVP Success Criteria

The MVP is successful if a user can:

1. Create a mission
2. Assign AI workers
3. Track progress
4. Store reflections
5. View operational state
6. Connect GitHub repositories
7. Continue iterative improvement

---

# 9. Phase Boundary

Phase 1:
ProductAI

Focus:
- building products
- mission orchestration
- memory
- dashboard operations

---

Phase 2:
BusinessAI

Focus:
- business operations
- KPI management
- CRM
- revenue
- growth intelligence

---

# 10. Long-term Vision

The ProductAI MVP aims to become:

The first operational step toward
an AI-supported software organization OS
that allows individuals and small teams
to build products through organizational intelligence.
